Flock Calendar

A care schedule for layer farms that asks a few setup questions, generates a calendar of recurring flock care, and lets the farmer see and check off what's due — so the routine lives in the app, not in his head.

Status: approved Markdown is canonical · this page is a companion

The core journey

First run asks a few questions → the app generates a calendar → the farmer sees and checks off what's due, and it's all still there next time.

Look and feel

Eco-friendly greens, lemon, and yellow. A farm vibe on a phone — plain, warm, readable, high-contrast enough for quick use outdoors. A bird logo; clear calendar section and list section. Avoid generic AI-app styling and clutter.

Features and behavior

1 Setup questionnaire click to collapse

On first run, asks: bird type; the caretaker's own schedule (student or worker); number of birds; how long they've lived (age); checkups per day; feedings per day; vaccine and deworm timing.

Inputs are constrained — you cannot enter something that makes no sense. From the answers, the app generates a suitable calendar; he can adjust it or add dates himself.

Completing setup produces a calendar with tasks on dates.
There is no way to submit an invalid value (zero birds, a nonsensical date).
2 The generated calendar click to expand

The app generates a default schedule from bird age and standard intervals; he can adjust it or enter dates manually. Multi-day tasks (e.g., deworming) span consecutive days.

The generated calendar reflects the bird age and the caretaker's schedule.
Editing a generated task updates the calendar.
3 Calendar and day list click to expand

The calendar shows dates; clicking a date opens the list. The list shows the selected day plus upcoming days. An empty day shows nothing, plus a way to add to that day.

Clicking a date shows that day's tasks and the following days'.
An empty day shows an empty list with an add affordance.
4 Tasks and check-off click to expand

Task types: checkup, feed, water, pick eggs (recurring, at the frequencies he set — his day runs morning, afternoon, night); cage cleaning (on some days); vaccines; deworming (multi-day).

Mark done with a checkbox. Marking day 1 of a multi-day task advances to day 2.

Checking a task clears it from the pending list for that day.
A 3-day deworming advances through days 1 → 2 → 3 as each is checked off.
5 Adding batches and custom tasks click to expand

Add another batch later (bird type, count, age). Add a custom task to any date.

A new batch appears with its own schedule.
A custom task appears on the chosen date.
6 History click to expand

A simple record of completed tasks.

A completed task appears in the history for its date.

States and boundaries

First use

Setup questionnaire, because nothing is configured yet.

Normal use

Calendar + day list.

Empty day

Empty list plus an add affordance.

Input

Constrained; invalid entries cannot be submitted (no error state needed for bad input).

Persistence

The schedule and the day's tasks remain between sessions; no account required.

Boundary

One caretaker; layers only; no sharing or multi-user.

What we're building

  • First-run setup questionnaire (constrained inputs).
  • Generated, editable calendar from bird age and intervals.
  • Calendar view with a day list (selected day + upcoming days).
  • Recurring daily tasks (checkup, feed, water, pick eggs) at set frequencies.
  • Cage cleaning on some days.
  • Vaccines and multi-day deworming.
  • Checkbox check-off; multi-day tasks advance.
  • Add another batch; add a custom task to any date.
  • A simple history of completed tasks.
  • Persistence between sessions; no account.
  • Mobile-friendly, eco farm look.

Deferred from the POC

→ Out for now click to expand
  • Notifications / reminders — the PoC proves the schedule, not delivery.
  • Other poultry and livestock — kept out so the demo stays sharp; the schedule should be data so this is cheap later.
  • Treatment records and notes per batch — later.
  • Reports and trends — later.
  • Native mobile app — the PoC is mobile-friendly; native is later.
  • Multi-caretaker / sharing — not needed to prove the kernel.
