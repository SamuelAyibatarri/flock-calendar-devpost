Flock Calendar — App Map

A care schedule for layer farms. Monday sets up his flock once, and the app generates a calendar of what each batch needs and when — feed, water, checkup, eggs, cage cleaning, vaccines, deworming — so he never holds the routine in his head.

What the app is, in pieces

Purpose: hold a layer farm's recurring care routine on the phone, with a generated calendar and daily check-off.

Main pieces:

  • src/app/setup.tsx — first-run questionnaire; generates the calendar from answers.
  • src/app/index.tsx — calendar screen (month grid); tap a date to see its tasks.
  • src/app/day/[date].tsx — day list (selected day + next 7 days) with check-off.
  • src/components/TaskRow.tsx — a single task row with checkbox.
  • src/components/BatchAdder.tsx, CustomTaskAdder.tsx — add another batch or a one-off task.
  • src/schedule/poultry.ts — the standard age-based layer-care rules.
  • src/schedule/build.ts — turns setup answers + standard rules into per-batch care rules.
  • src/schedule/rules.ts — "is this rule due on this date?" logic.
  • src/storage/store.ts — AsyncStorage: batches, rules, completions saved as one JSON file (flock:v1) on the phone.

One real action, traced through the code

Action: Monday checks off "Deworming day 1" for Batch A on June 4.

Reference route (2–3 stops)

This route was verified during build, not toured interactively — label it reference only.

1flock-calendar/src/app/index.tsx — CalendarScreen. Renders the month grid; tapping a date pushes /day/<date>. Also holds "Add batch"/"Add task" entry points.
2flock-calendar/src/app/day/[date].tsx — DayListScreen. handleCheck(ruleId, date) writes a Completion and filters it out of pending tasks; multi-day deworming advances automatically.
3flock-calendar/src/storage/store.ts — loadFlock / saveFlock wrap AsyncStorage under key flock:v1. Everything persists here; nothing lives in memory only.

To change this, start here

Change the care rules (vaccines, deworming, cleaning intervals): edit flock-calendar/src/schedule/poultry.ts — the STANDARD_LAYER_RULES array.
Change what counts as "due today": edit flock-calendar/src/schedule/rules.ts — the isRuleDueOn function.
Change the daily check-off screen: edit flock-calendar/src/app/day/[date].tsx and flock-calendar/src/components/TaskRow.tsx.
Change the setup questions: edit flock-calendar/src/app/setup.tsx and flock-calendar/src/schedule/build.ts.

A practice to reuse

The practice: derive the UI from stored data instead of storing the UI.

Flock Calendar doesn't save "what the calendar shows" — it saves batches, rules, and completions, and derives the calendar grid and day list on every render from those rules (src/schedule/rules.ts + src/storage/store.ts). That means adding a new task type or changing a schedule never requires migrating a saved calendar; you just change the rule logic and the view recomputes.

Where it's proven: slice 2's check-off mechanics were verified in isolation before wiring to the UI — the day-list filtering correctly removes completed tasks and advances multi-day deworming.

Reuse on another project: whenever you have a recurring schedule, store the rules (what, when, how often) and completions (what's done), then derive the view. Don't store "screen state" — store facts, compute presentation.

How to run it again

cd flock-calendar

bunx expo start — opens Expo DevTools; press a for Android emulator, i for iOS simulator, or scan the QR with Expo Go.

Note: @react-native-async-storage/async-storage has native code, so Expo Go won't include it. For a device/demo build, use bunx expo run:android or bunx expo run:ios (a development build) instead.

Implementation notes (reference)
  • All four build slices are complete and committed: setup+calendar, day list+check-off, add batch/custom task, empty day+polish.
